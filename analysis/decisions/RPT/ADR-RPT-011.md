# ADR-RPT-011 — RPT's four tables store codes and identifiers as VARCHAR2 at their owners' widths and free texts as CLOB; EMPLOYEE_DECISION and the seven consumed closed lists are CHECK constraints with no lookup table or seed rows; the report parts cascade from the Check Run on the purge; RPT has no XM
Status      : ACCEPTED
Stage       : P2        Module: RPT        Version: v1
Context     : The SRS gives every textual field the logical type `text`; the profile maps `text` to CLOB and `string` to VARCHAR2(n CHAR). CHK and DOC hand the CHECK constraints of their closed lists to RPT's columns (ADR-CHK-016, ADR-DOC-010) and the platform keeps no lookup table (ADR-REG-010). The purge deletes a Check Run with all its records (ADR-RPT-004, ADR-RPT-010). SRS A8 consumes nothing.
Decision    : (1) Codes, identifiers and names carried from other modules → VARCHAR2 at the width their owner's contract states (service code, document type, query name 100; host identifiers 100; closed codes 30; fetch mode 10); comparison model identifier VARCHAR2(200 CHAR); condition, evidence, note, detail and failure detail → CLOB (unbounded quoted values; a VARCHAR2(4000 CHAR) would exceed 4000 bytes for Arabic text under STANDARD string size). (2) EMPLOYEE_DECISION and CHECK_STATUS, OVERALL_STATUS, FINDING_OUTCOME, CHECK_FAILURE_REASON, FETCH_MODE (two columns), DOCUMENT_READ_STATUS, UNREADABLE_REASON as named CHECK constraints; no lookup table, no seed rows. (3) Shape CHECKs: result columns by status (CHK_RPT_CHECK_RUN_RESULT), AWAITING_DOCUMENTS only with `manual`, decision all-or-nothing on COMPLETED and never REJECTED through the Approval API, reason exactly on UNREADABLE, positions from 1. (4) The three report parts reference RPT_CHECK_RUN with ON DELETE CASCADE so one DELETE of a Check Run removes it whole in its transaction. (5) No XM: no column references another module and RPT reads no other module's data.
Alternatives rejected: All text as CLOB — codes could not carry CHECK constraints or indexes; lookup tables with seeds — duplicates the contracts' lists and contradicts ADR-REG-010; deleting children explicitly — same result with more statements, kept as the domain's fallback.
Consequences: P3.1 maps CLOB columns to String fields and enforces the not-blank rules in the domain; the purge issues one DELETE per expired Check Run.
