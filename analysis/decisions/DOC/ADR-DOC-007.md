# ADR-DOC-007 — UNREADABLE carries a reason from a closed list; a failed or over-limit document source query makes every required document type UNREADABLE
Status      : ACCEPTED
Stage       : P1        Module: DOC        Version: v1
Context     : ADR-DOC-002 requires a reason for every UNREADABLE document and lists the causes (outside the storage root, not found, too large, unsupported format, failed reading, out of time). A free-text reason cannot be tested or shown consistently. ADR-DOC-001 makes DOC run the document source query; when that query fails, exceeds the platform's maximum rows, or cannot run on its connection, DOC knows no document of the request — reporting the required types as MISSING would claim the host listed nothing, which is untrue, and truncating the rows silently breaks G6.
Decision    : (a) DOC masters the closed lookup UNREADABLE_REASON: OUTSIDE_STORAGE_ROOT, NOT_FOUND, TOO_LARGE, UNSUPPORTED_FORMAT, READING_FAILED, OUT_OF_TIME, SOURCE_QUERY_FAILED, MODEL_NOT_PERMITTED (ADR-DOC-009). Every UNREADABLE outcome carries one reason code and a detail text naming the failure. (b) If the document source query fails, returns more rows than the maximum rows of the platform configuration, or names a connection DOC must not use (not `jdbc` for `blob`, or not declared read-only), DOC fetches no document of that query and gives every required document type of the version an UNREADABLE outcome with reason SOURCE_QUERY_FAILED; a required document type is never MISSING because the query could not tell.
Consequences: RPT stores the reason code with the read status it receives through CHK (no RPT → DOC read, as ADR-DOC-002). CHK's deterministic check sees UNREADABLE required documents and cannot reach COMPLIANT (G6). Adding a reason is a new DOC version.
