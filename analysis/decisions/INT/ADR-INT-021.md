# ADR-INT-021 — Every screen read of the employee frontend binds INT's own read operations (API-INT-005 … API-INT-008); the mock server serves api-spec-int.yaml alone; the upload choices and the "no upload" list are the Check's own version's; supersedes ADR-INT-018 (1), (2), (3) and (7)
Status      : ACCEPTED
Stage       : P3.2      Module: INT        Version: v1
Context     : ADR-INT-018 bound the screens' reads to the owners' HTTP operations (API-RPT-001, API-RPT-002, API-REG-002, API-DOC-001), had the mock server serve four documents, recorded that no operation read the required document types of a Check's own version, and recorded that C9.5 / C9.24 report the foreign ids. ADR-INT-020 (P1 revision) made INT the single REST surface of the employee frontend: `api-spec-int.yaml` now carries API-INT-005 (a Check and its report), API-INT-006 (the Checks of a request), API-INT-007 (the uploaded documents of a Check, without content) and API-INT-008 (the required document types of the version the Check runs on), each relaying the owner's published operation.
Decision    : (1) Screen reads: SCR-INT-001 reads API-INT-006; SCR-INT-002 reads API-INT-005 (polled every 5 seconds while AWAITING_DOCUMENTS or RUNNING, stopped at COMPLETED or FAILED — ADR-INT-011 (4)); SCR-INT-003 reads API-INT-005 (status), API-INT-008 (choices) and API-INT-007 (uploaded documents); SCR-INT-004 reads API-INT-005, API-INT-007 and API-INT-008; SCR-INT-005 reads API-INT-005 (status and decision — REQ-INT-054). Writes unchanged: API-INT-001 … API-INT-004. No operation of another module's document is cited by the frontend plan. (2) The mock server of the frontend executor serves `api-spec-int.yaml` only. (3) The document type choices of an upload and the "no upload" list of the confirmation are the required document types of the version the Check runs on (API-INT-008); ADR-INT-018 (2)'s gap is closed; Document Access's DOC-422-DOCUMENT-TYPE-NOT-OF-SERVICE stays the final guard. (4) The screens' reads route INT's own codes: INT-400-REQUEST-INVALID, RPT-404-CHECK-NOT-FOUND and RPT-400-REQUEST-KEYS-MISSING (pass-through, owner's words), INT-500. (5) The UXD entries stay: the data's authoritative source is still the owner module, reached through INT's relay; each UXD names its owner module and the INT operation that serves it. (6) ADR-INT-018 (4), (5) and (6) — the launch context in the URL, the MISSING safeguard as ADR-INT-011 decided, en/ar labels with messages ar PENDING ADR-INT-017 — remain in force.
Consequences: The frontend plan binds only API-INT-* ids, so C9.5 and C9.24 resolve in `api-spec-int.yaml`; the frontend test plan runs against one mock document. API-INT-007's backend adapter waits on Document Access's in-process listing operation (ADR-INT-020 (4)); the frontend is built against the document and is unaffected. Non-breaking.
