# ADR-INT-024 — CHK v1 delivered: the Check Engine contract items INT cites (CON-CHK-001 … CON-CHK-005) are unchanged since INT's design, so INT's INT → CHK edge and every plan bound to it remain valid; resolves the XM event INT>CHK
Status      : ACCEPTED
Stage       : P1.5      Module: INT        Version: v1
Context     : The factory raised the XM resolution event INT>CHK (key INT>CHK@CHKv1:delivered) because the Check Engine (CHK) v1 was delivered and tagged after INT designed against it. INT depends on CHK over the platform edge INT depends_on CHK (ADR-INT-016) and cites these CHK contract items: CON-CHK-001 (Check status and Overall Status — closed lists), CON-CHK-002 (finding outcome), CON-CHK-003 (Check failure reason), CON-CHK-004 `startCheck(serviceCode, requestNumber, employeeId) → {checkId, status}` with its refusals (incomplete start, service not available, connection not activated) and CON-CHK-005 `confirmUploads(checkId) → {checkId, status}` with its refusals (Check not found, Check not waiting for documents). INT's PORTS adapter `ChkCheckEngineAdapter`, API-INT-001 and API-INT-003, the five CHK pass-through catalog rows (CHK-400-START-INCOMPLETE, CHK-422-SERVICE-NOT-AVAILABLE, CHK-422-CONNECTION-NOT-ACTIVATED, CHK-404-CHECK-NOT-FOUND, CHK-409-CHECK-NOT-AWAITING-DOCUMENTS) and their test cases are written against them. CON-CHK-006 … CON-CHK-011 (the Check result port and the Check reads) are RPT's and CHK's internal port and are not consumed by INT.
Decision    : (1) Verified: CHK's delivered contract (analysis/modules/CHK/P1_5/contract-chk.md, identical to CHK's _state/current-contract.md) last changed before INT's P0 began, and the five cited items carry the same signatures, closed code lists, refusals and messages INT's SRS A8, contract, backend plan (PORTS, API-INT-001, API-INT-003, error catalog) and test plans cite. No item INT depends on was added, changed or removed by the delivery. (2) The INT → CHK edge therefore remains valid as designed; no INT artifact changes and no plan is re-derived. (3) The event INT>CHK is answered with this ADR. A later CHK version that changes CON-CHK-001 … CON-CHK-005 raises a new event and is re-checked then.
Alternatives rejected: re-running INT's P1 … P4 against the delivered CHK — nothing INT cites changed, so a re-run would only reproduce the same artifacts.
Consequences: INT's XM event INT>CHK is resolved; INT's plans keep their CHK bindings unchanged. Non-breaking.
