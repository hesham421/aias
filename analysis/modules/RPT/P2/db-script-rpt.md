Module : RPT   Version : v1   Dialect : oracle19c   Schema prefix : none (objects created in the service's own schema)

Counts : 4 tables · 46 DBF · 0 XM · 0 sequences · 0 seed rows (ADR-RPT-011)
Identifier transformation : logical camelCase field → physical UPPER_SNAKE_CASE column (a capital letter starts a new word, joined by `_`), e.g. checkRunId → CHECK_RUN_ID. Tables `RPT_[entity abbreviation]`. Every name ≤ 128 bytes (oracle19c) and no reserved word.
PK generation : identity — every PK is `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY` (profile `pk_generation: identity`); no PK sequence, no PK trigger.
Header type note (ADR-RPT-011) : the SRS logical type `text` is split by use — codes, identifiers and names carried from other modules take the `string` syntax `VARCHAR2(n CHAR)` with the width their owner's contract states (service code, document type, query name `VARCHAR2(100 CHAR)` — CON-REG-001, CON-REG-003, CON-REG-004; host identifiers `VARCHAR2(100 CHAR)` — profile identifier rule; closed codes `VARCHAR2(30 CHAR)`, fetch mode `VARCHAR2(10 CHAR)` — CON-CHK-001 … CON-CHK-003, CON-DOC-001, CON-DOC-002; comparison model identifier `VARCHAR2(200 CHAR)`); free texts of unbounded length (condition, evidence, note, detail, failure detail) take `text` → `CLOB`. Version number `NUMBER(10)` (CON-REG-002); position `NUMBER(10)`; flag → `NUMBER(1)`; date-time → `TIMESTAMP WITH TIME ZONE`.

## 3. XM register

```yaml name=xm-register
records: []
```

RPT has no cross-module dependency at column or read level: its SRS A8 block consumes no entity (`consumes: []`). The service code, version number, document type, query name and every closed code arrive by value through the Check result port that CHK declares and RPT implements (CON-CHK-006 … CON-CHK-011; ADR-REG-002) and are stored as plain values — no column references another module's table and RPT reads no other module's data. The RPT → CHK edge stays the platform edge. CHECK_RUN_ID is RPT's own identifier, held by CHK, DOC and INT as a value (CON-RPT-001).
