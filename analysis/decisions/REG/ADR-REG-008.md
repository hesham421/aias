# ADR-REG-008 — REG states every raw-idea §12 guardrail at the surface it controls; the runtime enforcement stays with the module that runs it
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : Profile check AIAS-1 requires every guardrail of raw-idea §12 to be a REQ with at least one AC, and the owner made the §12 guardrails mandatory requirements of this version (A2). Several guardrails act at Check time in other modules (the LLM call in CHK, file opening in DOC, the approval call in INT), while REG holds only configuration (ADR-REG-001, ADR-REG-006). Writing CHK/DOC/INT behaviour into the REG SRS would be invented scope (no REG story asks for it) and would duplicate the owning module's requirements.
Decision    : Every §12 guardrail gets a REG requirement that constrains what REG accepts or supplies, traced to the REG story it serves: (1) LLM never writes SQL nor triggers approval → queries supplied only through the query channel, apart from the service knowledge (REQ-REG-030) and the approval API definition supplied only to the Employee Decision path (REQ-REG-044); (2) approval only on the employee's action → REQ-REG-044, REQ-REG-045; (3) read-only host access → a connection not declared read-only is refused (REQ-REG-055) and a query that is not a single SELECT statement is rejected (REQ-REG-033); (4) bound parameters, no SQL from free text → only named bind parameters of the declared input (REQ-REG-032); (5) file paths inside the storage root → a package holds no file location, document locations come only from host data through the path column (REQ-REG-041); (6) nothing skipped silently → every rejected package or connection is recorded in the load report (REQ-REG-007); (7) document content is data → the service knowledge is supplied as the only service instruction text, apart from query results and document content (REQ-REG-018); (8) per-Check limits → a service definition carrying its own timeout, row or file-size limit is rejected so the platform limits apply to every Check (REQ-REG-034, ADR-REG-006); (9) nothing carried between Checks → no request data in the registry and package content supplied read-only (REQ-REG-059, REQ-REG-060). The single-SELECT check is defence in depth beside the read-only database user (D2); it does not replace it.
Consequences: The CHK, DOC and INT SRSs carry the Check-time enforcement of guardrails 1, 2, 5, 6, 7 and 8; they read REG's guarantees, they do not re-validate them. P3.1 review (AIAS-3..AIAS-8) scores the enforcement where it runs.
