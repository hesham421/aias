# ADR-REG-017 — Service-code equality: trimmed, compared case-insensitively, stored in canonical lower case
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : The SRS never defined when two service codes are the same. RULE-REG-002 and UQ_REG_SVC_PKG_SERVICE_CODE compared raw text, so `scholarship-request`, `Scholarship-Request` and a trailing-space variant would register as three services, defeating POL-REG-001 (one package per service) and POL-REG-013 (codes come only from the registry — a consumer cannot guess the casing) (gate-analysis finding G4). The owner's standing recommendation: codes are trimmed and compared case-insensitively, stored in one canonical case.
Decision    : Every service code — declared by a package folder, or given to a read or an in-process request — is trimmed and compared case-insensitively. The canonical stored form is lower case (the delivered pilot code `scholarship-request` and every cross-module reference to it are already lower case, so no stored or published value changes; an upper-case canonical form would have renamed the pilot code everywhere). After trimming and lower-casing, a declared code must be 1–100 characters of `a-z`, `0-9` and single hyphens between them (`^[a-z0-9]+(-[a-z0-9]+)*$`); otherwise the package is rejected (RULE-REG-022, load reason REG-LOAD-INVALID-SERVICE-CODE). RULE-REG-002 compares canonical forms. The folder name is not required to equal the code (the code is what the definition declares). DB backstop: CHK_REG_SVC_PKG_SERVICE_CODE.
Consequences: SRS REQ-REG-064, REQ-REG-065, RULE-REG-022; P2 CHECK constraint; P3.1 canonicalisation in the load run, API-REG-002 and the in-process interface; P4 TCs.
traces      : REQ-REG-004, REQ-REG-064, REQ-REG-065, RULE-REG-002, RULE-REG-022, ENT-REG-001
