# ADR-REG-021 — A connection a stored blob-mode version reads its documents through stays of type jdbc: an activation that would change it is refused
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : RULE-REG-010 checks the blob-over-jdbc pairing only when a package is loaded. Connection activation may later update a registered Connection (REQ-REG-050) or re-register a removed one, and nothing stopped its type from changing to `mcp`; RULE-REG-017 (serve time) refuses only an absent connection. A blob-mode version validated against `main-db` (jdbc) would keep being supplied after `main-db` is re-activated as `mcp`, and DOC would read BLOB content over MCP — the case G14 / RULE-REG-010 exist to prevent (gate-analysis round 2, finding G2). Two remedies: refuse the activation change, or mark the affected versions unavailable at serve time.
Decision    : Refuse — the safer choice. When the activation configuration registers or updates a connection with a type other than `jdbc` while any stored version (current or older — older versions stay resolvable for pinned Checks, ADR-REG-020) has fetch mode `blob` and a document source query on that connection, the activation of that connection is refused: an existing Connection row keeps its previous settings unchanged (type, endpoint and every other field), a removed one is not re-registered, and the load report records one CONNECTION row REJECTED with the RULE-REG-025 message (load reason REG-LOAD-CONNECTION-TYPE-BREAKS-BLOB). The pairing check runs in activation, before packages are loaded, against the stored versions. An administrator who must retype the connection publishes a new version whose document source names a jdbc connection under another name; the old name stays jdbc. Marking versions unavailable was rejected: it would silently stop a live service because of a configuration typo, and it would still leave pinned Checks reading an MCP connection.
Consequences: SRS REQ-REG-072, RULE-REG-025, AC-REG-084, AC-REG-085; backend plan activation step and load reason code; backend TCs. No schema change.
