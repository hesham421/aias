# ADR-REG-022 — Text from the package directory or the activation configuration is length-checked before it is stored: an over-length value rejects its item; Load Result text is shortened, never refused
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : Only the service code is length-checked before storage (RULE-REG-022). A folder name or package directory path written as REG_LOAD_RESULT.SUBJECT_NAME (200), the reason (1000), a connection name (100) or endpoint (500) — and every other bounded value of a service definition or a connection — could exceed its VARCHAR2 column and raise a raw database error inside the single load-run transaction (ADR-REG-015), aborting the whole run instead of producing one REJECTED row and contradicting REQ-REG-007 (gate-analysis round 2, finding G4). Choice: reject the item, or truncate and store.
Decision    : Reject the item (the safer default) and never truncate stored configuration. (1) Before any insert or update, every text value a package folder or the activation configuration supplies for a bounded column is checked against that column's declared length in characters: folder name 200; inputName, queryName, query connectionName, documentSourceQueryName, documentType 100; documentTypeColumn, documentPathColumn, documentContentColumn 128; approvalApi 500; connectionName 100, endpoint 500, queryTool 100, dialect 30, credentialReference 200, environment name 50. A value that does not fit rejects that package or refuses that connection with the RULE-REG-027 message (load reason REG-LOAD-VALUE-TOO-LONG); an over-length environment name refuses every connection. (2) The Load Result row that records any outcome is itself never refused: its subjectName, serviceCode and reason are cut to 200, 100 and 1000 characters, the last kept character replaced by "…" when cut (RULE-REG-028) — this is the only truncation, and it touches report text only, never configuration. (3) The service code keeps its own rule (RULE-REG-022). The package directory path appears only on a PACKAGE_DIRECTORY row and is shortened by (2), never a reason to reject the load.
Consequences: SRS REQ-REG-073, REQ-REG-074, RULE-REG-027, RULE-REG-028, AC-REG-086 … AC-REG-090; backend plan validation order, activation step and load reason code; db-script DBF traces; backend TCs with an over-length directory path and an over-length connection name. No schema change.
