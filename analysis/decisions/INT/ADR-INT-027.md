# ADR-INT-027 — DOC v1 delivered: the INT → DOC edge remains valid, with DOC v1's additions (CON-DOC-006 and the two upload refusals DOC-409-CHECK-ENDED and DOC-422-UPLOAD-LIMIT-REACHED) now consumed by INT; resolves the XM event INT>DOC
Status      : ACCEPTED
Stage       : P4        Module: INT        Version: v1
Context     : The factory raised the XM resolution event INT>DOC because Document Access (DOC) v1 was delivered and tagged (doc-v1) after INT designed against it. INT depends on DOC over the platform edge INT depends_on DOC (ADR-INT-016) and cites these DOC contract items: CON-DOC-001 (document read status and unreadable reason, read in the report), CON-DOC-002 (fetch mode, read in the report), CON-DOC-003 `handOverUpload(checkId, serviceCode, versionNumber, documentType, fileName, fileContent)` with its refusals, and CON-DOC-006 `listUploadedDocuments(checkId)`. DOC v1, compared with what INT first designed against, added two things. (a) CON-DOC-006, the listing operation, which INT already binds through API-INT-007 (ADR-INT-023). (b) Two further refusals of CON-DOC-003: "Check already ended" (DOC-409-CHECK-ENDED, ADR-DOC-015) and "maximum uploads per Check reached" (DOC-422-UPLOAD-LIMIT-REACHED, ADR-DOC-016). INT now passes both through (ADR-INT-025, analysis-gate round 1 finding G1). CON-DOC-004 and CON-DOC-005 are CHK's operations and are not consumed by INT.
Decision    : (1) Verified against DOC's delivered contract (analysis/modules/DOC/P1_5/contract-doc.md). CON-DOC-003's signature is unchanged from what INT's DocumentAccessPort adapter calls, and its six refusals are now all in INT's contract (CON-INT-002), API document (API-INT-002), error catalog (23 rows, DOC pass-through 6), adapter note and test cases (TC-INT-096, TC-INT-097, TC-INT-102). CON-DOC-006 is bound unchanged (ADR-INT-023, TC-INT-095). CON-DOC-001 and CON-DOC-002 carry the same closed code lists INT's report screens show. (2) The INT → DOC edge therefore remains valid. The only INT changes the delivery called for are the additive ones of ADR-INT-025. No plan is re-derived and no id is renumbered. (3) The event INT>DOC is answered with this ADR. A later DOC version that changes CON-DOC-001, CON-DOC-002, CON-DOC-003 or CON-DOC-006 raises a new event and is re-checked then.
Alternatives rejected: re-running INT's P1 … P4 against the delivered DOC. Only the two refusals were missing, and ADR-INT-025 added them additively, so a re-run would only reproduce the same artifacts.
Consequences: INT's XM event INT>DOC is resolved, and INT's plans keep their DOC bindings together with the ADR-INT-025 additions. Non-breaking.
