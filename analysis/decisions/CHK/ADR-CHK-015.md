# ADR-CHK-015 — CHK keeps one transient entity, the Active Check: one row per unfinished Check with its status and deadline, deleted when the Check ends; it makes every Check end exactly once
Status      : ACCEPTED
Stage       : P1        Module: CHK        Version: v1
Context     : ADR-CHK-011 kept CHK free of any stored entity. The P2 database stage requires every module's script to carry a DB field traceability matrix with at least one column (factory block `dbf-matrix`, minItems 1, C0.1 CRITICAL), and every column needs an SRS entity origin — so the factory demands storage. Independently, the SRS has ending paths that can race on one Check: the timeout firing while the report is being stored, the upload window expiring while the employee confirms the uploads, start-up recovery. Nothing in CHK guarantees that exactly one ending reaches the result port and Document Access, and the deadlines exist only in memory. The owner allows CHK transient pipeline state where storage is demanded, provided CHK owns no report table (RPT owns the run, findings and Check Document rows — ADR-REG-001).
Decision    : (1) CHK owns ENT-CHK-001 Active Check (transactional, PRIVATE): activeCheckId (identity), checkId (the Check's identifier, RPT's, held as a value — never a foreign key), checkStatus (CHECK_STATUS, AWAITING_DOCUMENTS or RUNNING only), deadlineAt (end of the upload window or of the Check timeout), createdAt, updatedAt. (2) It is recorded when the Check run is created, updated on confirmation of the uploads, read for deadlines and for the confirmation check, and hard-deleted when the Check ends; whichever ending path deletes it ends the Check, and a path that finds it gone hands no further ending (REQ-CHK-076 … REQ-CHK-081; RULE-CHK-008 … RULE-CHK-010). (3) It holds no request data, result or document content (REQ-CHK-082, G9). (4) The start-up read of unfinished Checks stays on the result port (ADR-CHK-005; CON-CHK-011); the Active Checks of an earlier run are deleted after their Checks are ended INTERRUPTED. (5) This narrows ADR-CHK-011 point (1) from "no stored entity and no table" to "no report entity or table"; ADR-CHK-011 is otherwise unchanged.
Alternatives rejected: an invented column in a placeholder table — violates NO-COLUMN-INVENTION; the result port as the only arbiter of endings — needs a compare-and-set operation RPT has not designed, and would add an RPT round trip to every deadline check; storing pipeline working data — no requirement needs it and G9 forbids keeping it.
Consequences: P2 creates one CHK table; the contract is unchanged (the entity is PRIVATE and promised to no one). RPT's port stays as published.
