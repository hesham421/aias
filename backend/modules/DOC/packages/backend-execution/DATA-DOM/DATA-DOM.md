DTO MEMBERSHIP  create-request: none over HTTP (the in-process handover command carries checkId, serviceCode, versionNumber, documentType, fileName, file bytes; uploadedDocumentId, fileSize, oversized, createdAt, updatedAt are system-set) · update-request: none — no update exists (RULE-DOC-004) · response (API-DOC-001): uploadedDocumentId, documentType, fileName, fileSize, oversized, createdAt — never content, checkId echoed by the query
LOOKUP FIELDS  documentType → DOCUMENT_TYPE (open, consumed; values validated through XM-DOC-003) · serviceCode → SERVICE_CODE (open, consumed) — both store the code as a string, no FK
DOMAIN RULES
- RULE-DOC-001 — Upload only for a manual service · trigger: on upload handover · scope: CREATE
  - statement: The system shall reject an upload when the fetch mode of its service package version is not `manual`.
  - message (en): Documents can be uploaded only for a service whose documents are provided by the employee; the service "{serviceCode}" obtains its documents by "{fetchMode}". · message (ar): PENDING ADR-DOC-012
  - DB enforcement: app-level (fetch mode read through XM-DOC-001) · owner layer: service (UploadHandoverService)
- RULE-DOC-002 — Upload document type from the version's list · trigger: on upload handover · scope: CREATE
  - statement: The system shall reject an upload when its document type is not one of the required document types of its service package version.
  - message (en): "{documentType}" is not a document type of the service "{serviceCode}"; choose one of: {requiredDocumentTypes}. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: app-level (required types read through XM-DOC-003) · owner layer: service (UploadHandoverService)
- RULE-DOC-003 — Complete upload · trigger: on upload handover · scope: CREATE
  - statement: The system shall reject an upload when its Check identifier or document type is absent or its file has 0 bytes.
  - message (en): The upload needs a Check, a document type and a file that is not empty. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: CHK_DOC_UPLOADED_DOC_FILE_SIZE + NOT NULL on CHECK_ID, DOCUMENT_TYPE (+ app-level first) · owner layer: service
- RULE-DOC-004 — Uploaded Document is never changed · trigger: on any change attempt · scope: UPDATE
  - statement: The system shall refuse every change to an Uploaded Document after it is created.
  - message (en): An uploaded document cannot be changed; upload the corrected file as a new document. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: app-level — the repository declares no update method and the entity has no setters after construction (`@Immutable`) · owner layer: domain
- RULE-DOC-005 — Oversized upload kept without content and reported unreadable · trigger: on upload handover; on fetch · scope: CREATE, ALL (read)
  - statement: The system shall keep no content of an uploaded file larger than the maximum file size, mark its Uploaded Document oversized, and report it UNREADABLE with reason TOO_LARGE.
  - message (en): The file "{fileName}" is larger than the maximum file size of {maxFileSize}; it will not be read and will be reported as unreadable. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: CHK_DOC_UPLOADED_DOC_CONTENT (+ app-level size test against `aias.check.max-file-size`) · owner layer: service
- RULE-DOC-008 — Uploads serve only their own Check · trigger: on fetch in `manual` mode · scope: ALL (read)
  - statement: The system shall supply to a Check only the Uploaded Documents whose Check identifier equals that Check's identifier.
  - message (en): Uploaded document {uploadedDocumentId} belongs to another Check and was not used. (internal log — never shown to the employee) · message (ar): PENDING ADR-DOC-012
  - DB enforcement: every read filters `CHECK_ID = :checkId` (QR-DOC-001 and the fetch read) · owner layer: repository
- RULE-DOC-009 — No upload for an ended Check · trigger: on upload handover · scope: CREATE
  - statement: The system shall reject an upload when its Check identifier is recorded as an Ended Check.
  - message (en): The Check {checkId} has already ended; documents can no longer be uploaded for it. Start a new check to provide these documents. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: app-level (existence read on DOC_ENDED_CHECK.CHECK_ID DBF-DOC-013, served by UQ_DOC_ENDED_CHECK_CHECK_ID); the residual race is closed by the end-of-Check sweep (ADR-DOC-015) · owner layer: service (UploadHandoverService)
- RULE-DOC-010 — Maximum uploads per Check · trigger: on upload handover · scope: CREATE
  - statement: The system shall reject an upload when the number of Uploaded Documents of its Check already equals the maximum uploads per Check.
  - message (en): The Check {checkId} already has the maximum of {maxUploads} uploaded documents; no further file can be uploaded for it. · message (ar): PENDING ADR-DOC-012
  - DB enforcement: app-level (COUNT of DOC_UPLOADED_DOC by CHECK_ID DBF-DOC-002, IDX_DOC_UPLOADED_DOC_CHECK_ID, against `aias.check.max-uploads`) · owner layer: service (UploadHandoverService)
- RULE-DOC-006 and RULE-DOC-007 guard the connection settings read through XM-DOC-004; their full text is in the PORTS-QUERY sub-phase.
STATE MACHINE  none — no status column; created, read, deleted (≤ 2 states)
CROSS-MODULE   XM-DOC-001, XM-DOC-003 (validation of the handover) — the ids only
REPOSITORY OPS QR-DOC-001 (FIND_BY_CRITERIA, API-DOC-001); in-process SAVE, content FIND_BY_CRITERIA, COUNT and DELETE by CHECK_ID written inline in the SVC-API procedures (ADR-DOC-011)
