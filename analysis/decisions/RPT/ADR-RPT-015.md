# ADR-RPT-015 — RPT test plan derivation choices: open-list host values as placeholders, in-process operations as the exercised surface, closed-list CHECK constraints asserted inside the RULE-RPT-006/008/014 cases, frontend cases packaged on the F1–F4 phase units, no integration phase
Status      : ACCEPTED
Stage       : P4        Module: RPT        Version: v1
Context     : (a) The ACs name values of SERVICE_CODE and DOCUMENT_TYPE, both open host-data lists owned by the Service Registry (REG) with nothing seeded. The P4 engine requires a case naming such a value to create it through the owner's add-value call; REG publishes none (its HTTP surface is read-only and its packages are loaded from folders at start-up), and RPT never reads REG — it stores both values as text carried by value through the Check result port (ADR-RPT-001, ADR-RPT-011). (b) Every RPT write is in-process (ADR-RPT-006): 37 ACs have no HTTP operation to exercise. (c) The closed lists are enforced twice — the port's enums (RULE-RPT-006) and the CHECK constraints of db-script-rpt.md — and the owner asked for both to be tested. (d) RPT's frontend plan has no screen SUB (ADR-RPT-014). (e) RPT declares 0 XM and cites 0 UXD.
Decision    : (1) A case uses the placeholders ⟨SVC-A⟩, ⟨SVC-B⟩ (service codes) and ⟨DOC-TYPE-1⟩, ⟨DOC-TYPE-2⟩ (document types) where its AC names a REG value; the case passes the placeholder through the result port as an opaque text value, so no catalogue value is assumed and no add-value call is needed; the `Test data` line maps each placeholder to the AC's literal role. (2) A case on an in-process operation names it on its `Exercises` line (port operation + the contract item it implements) and reads results back through API-RPT-001 where its AC reads them; its package is PORTS for the result-port operations and the no-host-access / no-model guardrails, SVC-API for the reads, the decision procedure and the purge. (3) The cases of AC-RPT-018 (RULE-RPT-006), AC-RPT-020 (RULE-RPT-008) and AC-RPT-046 (RULE-RPT-014) carry a second step writing the out-of-list value directly into the service schema and assert the CHECK constraint refuses it — one case per AC still. (4) Frontend cases trace to the ACs whose Given/When names the employee frontend or the report it renders, and name one of F1–F4 as package. (5) INT-XM and INT-UXD are absent; MODEL-EVAL holds AC-RPT-057 (RPT sends no model request on any model change). (6) Arabic expectations stay `PENDING ADR-RPT-013`.
Alternatives rejected: inventing an add-value call for REG — a call no artifact publishes; moving the values into a product seed — forbidden for host data; omitting the CHECK-constraint assertion — the closed lists would be tested at one layer only.
Consequences: 60 backend cases (one per AC) and 10 frontend cases; every AC covered; every split unit that needs acceptance (PORTS, SVC-API, F1–F4) is named by ≥1 case. Non-breaking.
