# ADR-INT-015 — INT's db-script creates no table; its DBF matrix binds, read-only, the owners' columns INT reads through their contracts, so the factory's required DBF matrix and the RULE data sources resolve without inventing INT storage
Status      : ACCEPTED
Stage       : P2        Module: INT        Version: v1
Context     : ADR-INT-007 and ADR-INT-013 give INT no entity and no table (POL-INT-017, REQ-INT-059 — approved). The factory nevertheless requires every db-script to carry a `dbf-matrix` block with at least one row (factory `outputs.blocks`, C0.1), binds every RULE `Data source` field to the db-script (C6.9), and asks every backend API block to trace to a DBF (C7.3). Creating an INT table to satisfy the form would contradict the approved PRD (US-INT-012) — a breaking change. INT does read ten fields of other modules: the Check Run's identifier, status, service code, version number, request number, employee identity, decision and deciding employee (RPT, through CON-RPT-003 / CON-RPT-006) and the version's approval flag and approval API (REG, through CON-REG-012).
Decision    : (1) The FULL_DATABASE_SCRIPT holds no DDL and no DML — only comments stating that INT creates nothing; it runs as a no-op. (2) The DBF matrix carries one row per field INT reads, DBF-INT-001 … DBF-INT-010, each naming the owner's physical table and column as the owner's db-script defines them (RPT_CHECK_RUN, REG_SVC_PKG_VER) and the owner's ENT field; every row is a READ BINDING — the column is created, written and owned by RPT or REG, and INT neither creates, alters nor writes it, and never reads the table directly: the value arrives through the owner's in-process operation (XM-INT-001, XM-INT-002). `nullable` and `default` are left out because INT sets neither. (3) The two cross-module edges are SOFT-READ XM records, CONTRACTED on CON-RPT-001 and CON-REG-002. (4) The minimal-storage alternative (an INT approval-call log) is rejected: it breaks POL-INT-017; the executed-approval case of REQ-INT-039 goes to the service log.
Consequences: The backend plan binds by DBF-INT ids only and states, for C7.19, that INT writes none of them (owner-written). If a later version needs an INT audit record, it adds an entity and the first real DBF rows then.
