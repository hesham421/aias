# ADR-CHK-011 — The Check result port: the operations CHK declares and RPT implements; CHK owns no entity and keeps a Check's working data in memory only for that Check
Status      : ACCEPTED
Stage       : P1        Module: CHK        Version: v1
Context     : ADR-REG-001 gives RPT the Check run record, the findings and the Check Document rows; ADR-REG-002 makes CHK declare a result port that RPT implements so the graph stays acyclic; ADR-CHK-005 adds a read of the unfinished Checks at start-up; ADR-CHK-004 needs a waiting manual Check to be found again when the employee confirms the uploads, and the upload window to be checked. CHK must still answer "which Check, which version, which status" without a table of its own.
Decision    : (1) CHK owns no stored entity and no table; it declares the Check result port with these operations, all carrying values only: create a Check run (service code, version number, fetch mode, request number, employee identity, initial status, start time) → Check identifier (`NUMBER(19)`, RPT's); mark a Check RUNNING; complete a Check (Overall Status, findings, document outcomes without content, unread service queries, metadata, end time); fail a Check (one failure reason, detail text, end time); read one Check (identifier, status, service code, version number, fetch mode, request number, employee identity, start time); list the unfinished Checks (status AWAITING_DOCUMENTS or RUNNING, with start time). (2) RPT implements the port in its own version; CHK never reads RPT tables. (3) A Check's working data — the loaded service package, query results, document outcomes and content, model input and output — lives in memory for the running Check only and is discarded when it ends (G9). (4) A manual Check resumed on confirmation reloads exactly its recorded version through REG's resolve operation (CON-REG-009).
Alternatives rejected: a CHK table of transient pipeline state — no requirement needs data to outlive a running Check, and a restart ends every unfinished Check anyway (ADR-CHK-005); RPT's interface called directly — adds CHK → RPT and closes a cycle (ADR-REG-002).
Consequences: P1.5 publishes the port in CHK's contract; RPT's analysis implements it (handed to RPT). P2 creates no CHK table.
