# ADR-REG-016 — ServiceSummary carries `available`: a read of a withdrawn service says so
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : RULE-REG-016 refuses a read only for an unknown code, so GET /api/v1/services/{serviceCode} returns a withdrawn service's current version with 200, and ServiceSummary had no field that tells it apart from a live one; the list (API-REG-001) already filters to available services. INT's Document upload screen binds API-REG-002 (gate-analysis finding G3).
Decision    : ServiceSummary gains the required boolean `available` (true when the Service Package is available, false when withdrawn — DBF-REG-003). REQ-REG-013 and REQ-REG-014 return it; the list keeps returning available services only (so every list row has available = true); a read of a withdrawn code returns 200 with available = false. `available` reflects withdrawal only. Whether every connection of the current version is activated is not a summary field: that refusal (RULE-REG-017) belongs to the in-process supply to a Check, and a removed connection is visible in the load report (outcome REMOVED). Alternative rejected: a 404 for a withdrawn read — it would hide stored versions that stay resolvable (ADR-REG-003).
Consequences: Additive response change in v1 (no consumer is built yet): SRS REQ-REG-013, REQ-REG-014, AC-REG-014, AC-REG-015 and new AC-REG-081; contract CON-REG-008, CON-REG-010; api-spec ServiceSummary; P3.1 API-REG-001/002; P3.2 field list; P4 TCs.
traces      : REQ-REG-013, REQ-REG-014, AC-REG-081, ENT-REG-001
