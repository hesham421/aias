# ADR-DOC-012 — HTTP errors are PLATFORM-STD rows only; upload-handover rejections are typed in-process exceptions with codes INT maps to ProblemDetail; Arabic messages pending
Status      : ACCEPTED
Stage       : P3.1      Module: DOC        Version: v1
Context     : The error catalog's rows must each be answered by an operation of `api-spec-doc.yaml` (C7.30). DOC's user-facing rule messages (RULE-DOC-001, RULE-DOC-002, RULE-DOC-003, the RULE-DOC-005 notice, the unresolvable version of REQ-DOC-003) are raised by the in-process handover and fetch operations, which have no HTTP operation of their own (ADR-DOC-011); INT turns them into its HTTP responses. API-DOC-001 needs a check-identifier validation and a server-failure row that no RULE carries. The SRS gives messages in English only; the profile lists en and ar.
Decision    : (1) The error catalog carries only the errors of API-DOC-001: `DOC-400-CHECK-ID-REQUIRED` (missing or non-numeric checkId) and `DOC-500` (unexpected server failure), both PLATFORM-STD. (2) The handover and fetch rejections are typed exceptions of the `DocumentAccess` interface, each carrying a code in the profile format `{MOD}-{http}[-{SLUG}]` and the SRS message, listed in the plan's in-process rejection table: `DOC-422-FETCH-MODE-NOT-MANUAL` (RULE-DOC-001), `DOC-422-DOCUMENT-TYPE-NOT-OF-SERVICE` (RULE-DOC-002), `DOC-400-INCOMPLETE-UPLOAD` (RULE-DOC-003), `DOC-404-SERVICE-VERSION-NOT-FOUND` (REQ-DOC-003). INT maps each to a ProblemDetail with that code and status; the RULE-DOC-005 notice is a field of the handover result, not an error. RULE-DOC-006, RULE-DOC-007 and RULE-DOC-008 produce Document Outcomes or internal logs, never errors. (3) Arabic texts are `PENDING ADR-DOC-012` until the SRS carries them; nothing is translated here.
Consequences: INT's backend plan lists the four in-process codes in its own error catalog against its upload / check endpoints (recorded for INT). api-verify holds DOC only to the two catalog rows.
