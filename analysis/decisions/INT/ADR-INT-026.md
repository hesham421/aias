# ADR-INT-026 — Analysis-gate round 1 clarifications: same-type uploads passed through, background-poll failure keeps the shown Check, an invalid decision code tested, REQ-INT-057 worded without a modal, the P0 read-façade row annotated, and the partial-supersession status note
Status      : ACCEPTED
Stage       : P1        Module: INT        Version: v1
Context     : The round-1 analysis-gate review of INT v1 raised six MINOR findings (G3–G8). G3: module-registry's AUTO-DECISION row "INT adds no read façade" was never annotated as superseded by ADR-INT-020. G4: RULE-INT-002's invalid-decision-code half had no case. G5: REQ-INT-057 used the modal "may". G6: SCR-INT-002 did not say what one failed background poll does to a Check already on screen. G7: nothing said what happens when the employee uploads a second document of the same type before confirming. G8: ADR-INT-001, ADR-INT-017 and ADR-INT-018 remain ACCEPTED or RESOLVED-IN-DIALOGUE although later ADRs supersede some of their numbered points.
Decision    : (1) G7. Document Access accepts several uploads of one document type for a Check. A correction is a new upload, and the earlier one is never changed (REQ-DOC-023, AC-DOC-025). INT passes every such upload through as its own handover and never removes, replaces or picks among same-type uploads. Both are listed (REQ-INT-063), and which uploads the Check reads is Document Access's concern (CON-DOC-004). New REQ-INT-065 and AC-INT-077 state this. The upload screen (SCR-INT-003) marks a document type that already has an upload in its choice list and still offers it. (2) G6. The first read of a Check that fails shows the screen's error state with a retry action. A later background poll that fails keeps the last Check read successfully on screen and shows a non-blocking notice ("Could not refresh; retrying"). The next interval retries, and a successful read removes the notice. New REQ-INT-066 and AC-INT-078 state this. P3.2 records it in SCR-INT-002's States row and in the frontend plan's report data hook, and P4 adds a frontend case. (3) G4. New AC-INT-079 under REQ-INT-034 covers an employeeDecision outside {APPROVED, REJECTED}, and P4 adds a backend case. (4) G5. REQ-INT-057 is reworded to "operations published in the REST API document for every host system". The meaning does not change. (5) G3. The P0 AUTO-DECISION row is annotated with its supersession by ADR-INT-020. (6) G8 is a factory schema gap, not an INT defect, and is recorded here as a note only. The ADR status enum (shared/GOVERNANCE-CORE.md: ACCEPTED | BLOCKED | SUPERSEDED) cannot express partial supersession. The points superseded so far are ADR-INT-001's no-read part (by ADR-INT-020), ADR-INT-011 (5)'s current-version part (by ADR-INT-020), ADR-INT-017 (1) (by ADR-INT-020) and ADR-INT-018 (1), (2), (3) and (7) (by ADR-INT-021). ADR-INT-018 (4), (5) and (6) stay binding. The ADRs are not rewritten, and their Status lines stay as they are until the factory adds a "Superseded (partial)" field.
Alternatives rejected: for G7, "the latest upload of a type wins". INT would then decide which document the Check reads, which is Document Access's and the Check Engine's job. For G6, replacing the report with an error screen on one dropped poll; a transient network error would hide a valid report.
Consequences: P0 (one annotation), P1 (REQ-INT-065, REQ-INT-066, AC-INT-077, AC-INT-078, AC-INT-079, REQ-INT-057 wording), P3.2 (SCR-INT-002 and SCR-INT-003 states, frontend plan) and P4 (new cases) change additively. Non-breaking.
