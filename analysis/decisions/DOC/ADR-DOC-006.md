# ADR-DOC-006 — A manual upload is handed over with its Check's service package version, validated against it, and an oversized file is kept without content and reported unreadable
Status      : ACCEPTED
Stage       : P1        Module: DOC        Version: v1
Context     : ADR-DOC-003 makes the Uploaded Document DOC-private, bound to one Check by the Check's identifier as a value, typed by the employee with "one of the service's document types". DOC never reads RPT (tier 3), so it cannot look up the Check's service by itself. POL-DOC-006 makes uploads meaningful only in `manual` mode. POL-DOC-012 names "Upload document" as a trigger of the maximum file size rule and says an oversized document is not read and is reported unreadable.
Decision    : (a) INT hands each upload over with the Check's identifier, the service code and version number of the Check, the file name, the file content and the document type the employee gave. DOC resolves that version through the REG interface (CON-REG-009) and rejects the upload when the version's fetch mode is not `manual` (RULE-DOC-001) or when the document type is not one of the version's required document types (RULE-DOC-002); an upload without a Check identifier, a document type or file content is rejected (RULE-DOC-003). The service code and version number are stored on the Uploaded Document as values, never as foreign keys. (b) An uploaded file larger than the maximum file size is recorded as an Uploaded Document marked oversized and without its content; the handover answers with a notice to the employee, and the Check reports it UNREADABLE with reason TOO_LARGE (RULE-DOC-005). This keeps POL-DOC-012 literal ("not read, reported as unreadable") while no oversized content is kept. (c) An Uploaded Document is never changed; a corrected file is a new upload (RULE-DOC-004). Several uploads of one document type are allowed; each gets its own outcome.
Alternatives rejected: rejecting an oversized upload outright — the document would then appear as MISSING instead of UNREADABLE, contrary to POL-DOC-012; accepting any document type — a type outside the service's list could never satisfy a required document and would only add noise.
Consequences: INT must pass the service code and version number of the Check with every upload (recorded for the INT analysis). P2 stores no oversized content. The P3.1 handover operation returns the rule messages for INT to show.
