# ADR-CHK-018 — HTTP errors are PLATFORM-STD rows of API-CHK-001 only; start and confirmation rejections are typed in-process exceptions with codes INT maps to ProblemDetail; Arabic messages pending
Status      : ACCEPTED
Stage       : P3.1      Module: CHK        Version: v1
Context     : The error catalog's rows must each be answered by an operation of `api-spec-chk.yaml` (C7.30). CHK's user-facing refusals (REQ-CHK-004, RULE-CHK-001, REQ-CHK-006, REQ-CHK-058, RULE-CHK-010) are raised by the in-process start and confirmation operations, which have no HTTP operation of their own (ADR-CHK-017); INT turns them into its HTTP responses. API-CHK-001 needs a not-found row, an identifier validation row and a server-failure row that no RULE carries. The SRS gives messages in English only; the profile lists en and ar.
Decision    : (1) The error catalog carries only the errors of API-CHK-001: `CHK-400-CHECK-ID-INVALID`, `CHK-404-ACTIVE-CHECK-NOT-FOUND`, `CHK-500`, all PLATFORM-STD. (2) The start and confirmation rejections are typed exceptions of the `CheckEngine` interface, each with a code in the profile format `{MOD}-{http}[-{SLUG}]` and the SRS message, listed in the plan's in-process rejection table: `CHK-400-START-INCOMPLETE` (REQ-CHK-004), `CHK-422-SERVICE-NOT-AVAILABLE` (RULE-CHK-001), `CHK-422-CONNECTION-NOT-ACTIVATED` (REQ-CHK-006), `CHK-404-CHECK-NOT-FOUND` (REQ-CHK-058), `CHK-409-CHECK-NOT-AWAITING-DOCUMENTS` (RULE-CHK-010). INT maps each to a ProblemDetail with that code and status. Pipeline outcomes (unread queries, UNDETERMINED findings, FAILED reasons) are results handed to the result port, never errors. (3) Arabic texts are `PENDING ADR-CHK-018` until the SRS carries them; nothing is translated here.
Consequences: INT's backend plan lists the five in-process codes in its own error catalog against its start and upload-confirmation endpoints (handed to INT).
