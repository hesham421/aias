# ADR-DOC-010 — DOC's closed lookups back no DOC column and get no lookup table or seed rows; the Uploaded Document stores its file as a BLOB with a CHECK tying content to the oversized flag
Status      : ACCEPTED
Stage       : P2        Module: DOC        Version: v1
Context     : SRS A6 gives DOC three closed keys — FETCH_MODE (carried by value on ENT-REG-002.fetchMode, already enforced by REG's CHECK constraint), DOCUMENT_READ_STATUS and UNREADABLE_REASON (carried on the transient Document Outcome, stored by RPT). None of them is a field of ENT-DOC-001. The P2 engine asks for seed rows for every key a module owns, but forbids columns without SRS origin, and the platform has no lookup table (ADR-REG-010). The syntax map of the profile has no binary type, while ENT-DOC-001.content is a file of logical type binary.
Decision    : (a) No lookup table and no seed INSERT is emitted for FETCH_MODE, DOCUMENT_READ_STATUS or UNREADABLE_REASON: they are closed enums of the service code (CON-DOC-001, CON-DOC-002) and the CHECK constraints sit on the columns that store them — REG_SVC_PKG_VER.FETCH_MODE today, RPT's Check Document columns when RPT is analysed. (b) Logical `binary` maps to `BLOB`, declared once in the script header. (c) The Uploaded Document carries CHECK constraints for RULE-DOC-003 (file size > 0) and RULE-DOC-005 (content present exactly when not oversized). (d) CHECK_ID, SERVICE_CODE and VERSION_NUMBER are plain value columns — no foreign key and no XM (ADR-DOC-003, ADR-DOC-006; the contract of REG stores the business key by value).
Consequences: The backend plan's bootstrap names the service code enums as the source of DOC's closed values; RPT's P2 must put the CHECK constraints for DOCUMENT_READ_STATUS and UNREADABLE_REASON on its own columns (recorded for RPT). Adding a value is a new DOC version.
