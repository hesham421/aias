# ADR-INT-013 — Host Integration declares no entity of its own; its rules name as data source the fields of the Report Store's Check Run and the Service Registry's Service Package Version that it reads through their contracts, and it owns no lookup
Status      : ACCEPTED
Stage       : P1        Module: INT        Version: v1
Context     : ADR-INT-007 gives INT no storage. The SRS template asks every RULE for a `Data source` naming declared entity fields, and the A6 lookups block for every lookup the module owns. INT's rules read the Check's status, decision and launch identifiers (CON-RPT-003 → ENT-RPT-001) and the version's approval flag (CON-REG-012 → ENT-REG-002).
Decision    : (1) A3 declares no ENT-INT; it lists the consumed fields INT reads, by their owners' ids. (2) Every RULE's `Data source` names those consumed fields (ENT-RPT-001.checkStatus, ENT-RPT-001.employeeDecision, ENT-RPT-001.decidedBy, ENT-RPT-001.serviceCode, ENT-RPT-001.requestNumber, ENT-RPT-001.employeeId). (3) `module-dependencies` consumes ENT-RPT-001 (RPT) and ENT-REG-002 (REG), both SOFT-READ through the in-process interfaces; CHK and DOC promise no entity INT reads, so the INT → CHK and INT → DOC edges stay the platform edges. (4) `lookups: []` — every code INT passes is owned by CHK, DOC, RPT or REG.
Consequences: P2 creates no table; its db-script records the data-source bindings to the owners' fields and the cross-module edges as XM records, with no column and no constraint.
traces      : RULE-INT-001, RULE-INT-002, RULE-INT-003, RULE-INT-004, US-INT-003, US-INT-006, US-INT-008, US-INT-012
