# ADR-RPT-020 — A Check run kept by the purge because its deletion failed is logged with its identifier and the cause (REQ-RPT-054); no new rejection code
Status      : ACCEPTED
Stage       : P1        Module: RPT        Version: v1
Context     : REQ-RPT-052 (AC-RPT-060) keeps an expired Check run whole and continues when its deletion fails, and REQ-RPT-046 logs only the number deleted and the cut-off (ADR-RPT-010). Neither asks for the kept Check run to be named, so a Check run whose deletion fails on every run (a lock, a constraint) is visible only as a count that stays one short each night — a counter-case of the raw-idea §12 guardrail "nothing skipped silently" (gate-analysis round 2, finding G8). The reviewer left open whether to extend REQ-RPT-052 or add a sibling REQ.
Decision    : (1) A new unwanted-pattern requirement REQ-RPT-054 with AC-RPT-064, rather than widening REQ-RPT-052: REQ-RPT-052 keeps one obligation (keep the Check run whole and continue), REQ-RPT-054 states a separate, independently testable one (log the identifier and the cause), which keeps each requirement singular (ISO/IEC/IEEE 29148) and leaves AC-RPT-060 unchanged. (2) The log line, written at WARN before the purge moves to the next Check run, is "Report purge kept Check run {checkId}: its deletion failed ({cause})." where {cause} is the failure's message as the database reports it, never row content. (3) The closing count line of REQ-RPT-046 is unchanged and still counts deleted Check runs only. (4) No new rejection code: the purge has no caller, so nothing is refused.
Alternatives rejected: extending REQ-RPT-052's Statement with a second "shall" — two obligations in one requirement; logging only a count of failed deletions — still does not say which Check run is stuck; raising an alert or stopping the purge — outside RPT v1's scope and against REQ-RPT-052's "continue".
Consequences: P3.1 names REQ-RPT-054 in ReportPurgeService step 3 with the log line; P4 adds one backend case (fault-injected deletion failure, log asserted). No contract, API or database change. Non-breaking.
