# ADR-REG-011 — The start-up load run and the in-process interface are service-layer procedures, not API blocks; load-time rule messages are load reasons, not HTTP errors
Status      : ACCEPTED
Stage       : P3.1      Module: REG        Version: v1
Context     : ADR-REG-007 gives REG no HTTP write operation: packages and connections are written only by the start-up load run, and CHK, DOC, RPT and INT read REG in-process (CON-REG-007, CON-REG-009, CON-REG-011, CON-REG-012, CON-REG-013). The P3.1 engine models endpoints as `API-*` blocks derived 1:1 into the OpenAPI document, wants every `QR-*` reached by an `API-*` (C7.22), and wants every user-facing RULE message as an error-catalog row answered by an HTTP response (C7.30). Load-time rules (RULE-REG-001 … RULE-REG-015, RULE-REG-018 … RULE-REG-020) never answer an HTTP request: their outcome is a Load Result row. The SRS gives every message in English only, while the profile lists en and ar with `require_all: false`.
Decision    : (1) Only the three HTTP read operations are `API-*` blocks (API-REG-001 … API-REG-003) and appear in `api-spec-reg.yaml`. The load run (activation, package validation, version registration, withdrawal) and the in-process `ServiceRegistry` interface are specified in the SVC-API phase as service-layer procedures, each with its `Honours: CON-…` line, its rule text and its persistence intent written inline against exact tables and `DBF-*` ids. The QR catalog carries the queries reached by the API blocks; the load-run and in-process persistence is not catalogued under `QR-*`. (2) A load-time rule message is stored as the Load Result `REASON` (DBF-REG-047) behind a load reason code `REG-LOAD-{SLUG}` listed in the plan's load reason table; it is not an error-catalog row. The error catalog carries only HTTP errors: RULE-REG-016 → `REG-404-SERVICE-NOT-FOUND`, and `REG-500` as PLATFORM-STD for an unexpected server failure. RULE-REG-017 and the in-process not-found cases are typed exceptions of the in-process interface, also listed in the load reason table's in-process section. (3) Arabic message texts are `PENDING ADR-REG-011` — the SRS states English only and inventing translations is forbidden; they are added when the SRS carries them.
Consequences: The frontend and test stages bind only to the three GET operations. The test stage derives load-run test cases from the ACs through the load report (API-REG-003) and the in-process interface. A later version that adds a hot-reload endpoint turns the load run into an `API-*` block and catalogues its queries.
