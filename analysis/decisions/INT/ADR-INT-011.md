# ADR-INT-011 — The employee frontend is opened by the host with the service code, request number and employee identity of one request; it shows the Overall Status as stored, never presents COMPLIANT beside a MISSING document outcome, shows every text as plain text, refreshes a Check that has not ended every 5 seconds, and reads its lists from their owners' HTTP reads
Status      : ACCEPTED
Stage       : P1        Module: INT        Version: v1
Context     : A1 embeds the frontend in the host screen for one request; the employee identity is passed by the host and recorded as sent (A2). The Overall Status is derived by CHK — a missing or unreadable required document gives a finding that is not SATISFIED, so the report is not COMPLIANT (CON-CHK-001, CON-CHK-002) — and the Report Store refuses to store COMPLIANT unless every finding is SATISFIED (RULE-RPT-005). AIAS-11 requires that a report with a missing or unreadable required document is never displayed as COMPLIANT. Document Access gives a MISSING outcome only for a required document type that no document carries (CON-DOC-004). The reads the screens need are served by RPT (Check, Checks of a request), REG (the service with its required document types) and DOC (uploaded documents of a Check).
Decision    : (1) Launch context: the host opens the frontend with a service code, a request number and an employee identity; without all three the frontend shows no Check and the RULE-INT-004 message. The employee identity of the launch is the one sent when the employee starts a Check or records a decision. (2) The frontend never derives an Overall Status; it presents the stored one. As a display safeguard, a report holding a MISSING document outcome is never presented as COMPLIANT — it is presented as "Not verified — a required document is missing" — and every UNREADABLE document is shown with its reason beside the status. (3) Evidence, notes, conditions, details and file names are shown as plain text, never interpreted as markup or followed as links (raw idea §12 'document content is data'). (4) While a shown Check is AWAITING_DOCUMENTS or RUNNING, its read is repeated every 5 seconds (frontend configuration) and stops when it is COMPLETED or FAILED. (5) The document type choices of an upload are the required document types of the Check's service from REG's service read; a type the Check's own version does not hold is refused by Document Access (DOC-422-DOCUMENT-TYPE-NOT-OF-SERVICE).
Consequences: P3.2 designs five screens (SCR-REQ-INT-001 … SCR-REQ-INT-005) on INT's four write operations and the owners' reads; no INT read operation is added. The polling interval is a frontend configuration value.
