DOMAIN RULES
- RULE-CHK-008 — One Active Check per Check · trigger: on recording an Active Check · scope: CREATE
  - statement: The system shall refuse to record a second Active Check for a Check identifier that already has one.
  - message (en): Check {checkId} already has an Active Check; the second start of its pipeline was not run. (internal log — never shown to the employee) · message (ar): PENDING ADR-CHK-018
  - DB enforcement: UQ_CHK_ACTIVE_CHECK_CHECK_ID · owner layer: repository (a duplicate-key violation is caught, logged with the message and the pipeline is not started a second time)
- RULE-CHK-009 — Active Check only for an unfinished status · trigger: on recording or updating an Active Check · scope: CREATE, UPDATE
  - statement: The system shall accept for an Active Check only the status AWAITING_DOCUMENTS or RUNNING.
  - message (en): An Active Check can only be AWAITING_DOCUMENTS or RUNNING; status {checkStatus} was not stored. (internal log — never shown to the employee) · message (ar): PENDING ADR-CHK-018
  - DB enforcement: CHK_CHK_ACTIVE_CHECK_CHECK_STATUS + the `ActiveCheckStatus` enum (COMPLETED / FAILED are not representable) · owner layer: domain
- RULE-CHK-010 — Uploads confirmed only for a Check waiting for documents · trigger: on confirming the uploads of a Check · scope: UPDATE
  - statement: The system shall refuse a confirmation of uploads when the Check has no Active Check with status AWAITING_DOCUMENTS.
  - message (en): Check {checkId} is not waiting for documents; its status is {status}. · message (ar): PENDING ADR-CHK-018
  - DB enforcement: app-level — locking read `SELECT … FOR UPDATE` on CHK_ACTIVE_CHECK by CHECK_ID (DBF-CHK-002) and test of CHECK_STATUS (DBF-CHK-003) · owner layer: service (CheckConfirmationService) · in-process code CHK-409-CHECK-NOT-AWAITING-DOCUMENTS
- The guard rules of the pipeline (RULE-CHK-001 … RULE-CHK-007) read service registry data only and carry no column of this table; their full text is in PORTS-QUERY and SVC-API.
STATE MACHINE  status column CHECK_STATUS (DBF-CHK-003) · values AWAITING_DOCUMENTS, RUNNING · initial AWAITING_DOCUMENTS (`manual` service) or RUNNING (`path` / `blob`) · transition AWAITING_DOCUMENTS → RUNNING on confirmation (RULE-CHK-010) · terminal: the row is deleted when the Check ends COMPLETED or FAILED (REQ-CHK-078) — the deletion is the one place that decides which ending path wins (REQ-CHK-079, ADR-CHK-015)
CROSS-MODULE   none — CHECK_ID is a value; no edge touches this entity
REPOSITORY OPS QR-CHK-001 (FIND_ONE, API-CHK-001); in-process SAVE, locking FIND_ONE, UPDATE, deadline FIND_BY_CRITERIA and DELETE by CHECK_ID written inline in the SVC-API procedures (ADR-CHK-017)
