# ADR-REG-018 — An unreachable or empty package directory fails safe: nothing is withdrawn and the load report says why
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : REQ-REG-010 withdraws every stored service code that has no folder. A missing, unreadable or empty package directory (a wrong path, a failed volume mount) would withdraw every service at the next start, and every Check would be refused, with no trace distinguishing it from an administrator who removed every folder (gate-analysis finding G5; raw idea §12 "nothing is skipped silently").
Decision    : When the configured package directory does not exist or cannot be read, or exists but holds no package folder while the registry holds at least one available Service Package, the load run loads no package, registers no version and withdraws or restores no service: the registry keeps its previous state and stays usable. It records one Load Result with subject kind PACKAGE_DIRECTORY (new closed LOAD_SUBJECT value), subject name = the configured directory path, outcome REJECTED and the reason of RULE-REG-023 (load reason REG-LOAD-PACKAGE-DIRECTORY-UNAVAILABLE). Connection activation still runs (it reads a different source). Retiring every service remains possible by removing the folders one start at a time or emptying the directory while the registry holds no available service — v1 offers no "withdraw all" act. An empty directory with no available service in the registry is a normal, empty load.
Consequences: SRS REQ-REG-066, RULE-REG-023, LOAD_SUBJECT gains PACKAGE_DIRECTORY; P2 widens CHK_REG_LOAD_RESULT_SUBJECT_KIND; P3.1 guard before package loading; api-spec LoadResult.subjectKind enum; P4 TCs.
traces      : REQ-REG-010, REQ-REG-066, RULE-REG-023, ENT-REG-001, ENT-REG-006
