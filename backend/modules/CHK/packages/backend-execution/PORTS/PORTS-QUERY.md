### SUB PORTS-QUERY
- `ServiceQueryPort` (port) — `run(sqlText, inputName, requestNumber, connectionSettings, maxRows, remainingTime) → QueryResult {rows | notRead(detail)}`. Contract: the SQL text is sent **exactly as stored** (REQ-CHK-011); the request number is passed as ONE bound value under the parameter `:{inputName}`, never concatenated, whatever characters it holds (REQ-CHK-012; AIAS-5); the limit `maxRows + 1` is requested so an over-limit result is detected, never truncated (REQ-CHK-050); the call's timeout is the time left before the Check timeout (REQ-CHK-016).
- `McpServiceQueryAdapter` (adapter) — calls the platform MCP query channel (the injected query-executor bean of the platform track — the Spring AI MCP client calling the connection's query tool) with the bound value, the row limit and the timeout. It is the only way CHK reaches host data (REQ-CHK-013); no JDBC connection is ever opened by CHK (REQ-CHK-018).
- Selection: the queries of the Check's version (read through XM-CHK-003) minus the one whose name equals the version's document source query name (read through XM-CHK-002):
  - RULE-CHK-005 — Document source query left to Document Access · trigger: on running the service queries · statement: The system shall skip the service query whose query name equals the version's document source query name. · message (en): Query "{queryName}" is the document source query; Document Access runs it. (internal log — never shown to the employee) · message (ar): PENDING ADR-CHK-018 · effect: the query is never sent by CHK (REQ-CHK-015).
- Guards run **before** each query is sent (connection settings read through XM-CHK-005):
  - RULE-CHK-002 — Service queries only over a read-only MCP connection · trigger: on each service query, before it is sent · statement: The system shall refuse to send a service query whose named connection is not of type `mcp` or is not declared read-only. · message (en): The data of query "{queryName}" was not read: connection "{connectionName}" is not a read-only MCP connection. · message (ar): PENDING ADR-CHK-018 · effect: the query is recorded as not read with the message as detail; the Check continues (REQ-CHK-014).
  - RULE-CHK-003 — Request number only as the bound input parameter · trigger: on each service query, before it is sent · statement: The system shall bind the Check's request number to the parameter named by the version's input name and shall refuse to send a query whose text would have to be changed to carry it. · message (en): The data of query "{queryName}" was not read: it has no bind parameter "{inputName}" for the request number. · message (ar): PENDING ADR-CHK-018 · effect: not read with the message as detail (REQ-CHK-012).
- A query error → not read with the error text as detail (REQ-CHK-049); more than `maxRows` rows → not read with detail "more than {maxRows} rows" and none of its rows kept (REQ-CHK-050). Unread entries are carried to the report as `UnreadQuery {queryName, detail}` (ADR-CHK-014).
