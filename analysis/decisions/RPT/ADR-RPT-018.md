# ADR-RPT-018 — The Check result port's value types are closed to exactly the fields CON-CHK-008 and CON-CHK-009 declare; a hand-over with an undeclared field is refused structurally (REQ-RPT-053), with no new rejection code
Status      : ACCEPTED
Stage       : P1        Module: RPT        Version: v1
Context     : US-RPT-005's requirements stated only the ubiquitous guarantees (REQ-RPT-019: no document content kept), not the unwanted path of a completeCheck / failCheck hand-over carrying a field the contract does not declare (gate-analysis finding G3, C5.16). The port is in-process (profile `conventions.module_interface: in_process`; ADR-RPT-006, ADR-RPT-012): there is no wire format and no deserialization step at which an extra field could be detected and refused at run time. An out-of-list value in a declared code field is already refused by RULE-RPT-006 (RPT-422-UNKNOWN-CODE).
Decision    : (1) REQ-RPT-053 (unwanted) states the refusal; AC-RPT-061 makes it measurable. (2) It is enforced structurally: completeCheck and failCheck accept only Java records whose components are exactly the CON-CHK-008 / CON-CHK-009 fields — finding {condition, outcome, evidence, note}; document outcome {documentType, sourceMode, readStatus, reason, detail}; unread query {queryName, detail}; metadata {serviceCode, versionNumber, fetchMode, comparisonModel, employeeId, startedAt, endedAt}; failCheck (checkId, failureReason, detail, endedAt) — with no map, byte array or untyped-object component and no "extra attributes" holder, so a hand-over with an undeclared field cannot be constructed and nothing of it is written. (3) No new rejection code: an undeclared value in a declared code field stays RPT-422-UNKNOWN-CODE (RULE-RPT-006). (4) P4 asserts the record components reflectively (one case for AC-RPT-061).
Alternatives rejected: a new RPT-422-UNEXPECTED-FIELD code with a runtime strict-deserialization rule — there is nothing to deserialize in-process, so the code would be unreachable; an open map validated at run time — weaker than a closed type and invites content to be carried.
Consequences: P3.1 lists REQ-RPT-053 among the result-port REQs and states the closed value types; P4 adds one case. Contract-chk.md is unchanged (RPT implements it as written). Non-breaking.
