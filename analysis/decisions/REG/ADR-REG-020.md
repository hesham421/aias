# ADR-REG-020 — One Check reads one version: CHK resolves and pins the version; every later read inside the Check uses the version-pinned lookup
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : CON-REG-007 (getCurrentServicePackage) answers with whatever version is current at the moment of the call. CON-REG-007 lists DOC as an independent caller (fetch mode, document source, required document types), while the version-pinned lookup CON-REG-009 lists only RPT and CHK. If a load run makes version N+1 current after CHK resolved version N for a Check but before DOC's document-fetch step of that same Check, DOC would read N+1 while CHK's report records N — two consumers of one Check silently disagreeing (gate-analysis round 2, finding G1). DOC v1 is already delivered (tagged doc-v1) and calls CON-REG-007, so CON-REG-007's signature cannot change in REG v1 (non-breaking only).
Decision    : (1) The version of a Check is the one CHK resolves through CON-REG-007 at the start of that Check and pins (serviceCode + versionNumber). (2) Every later read of service configuration inside that Check, by any consumer (CHK, DOC, RPT, INT), reads the pinned version through CON-REG-009 getServicePackageVersion(serviceCode, versionNumber), which always returns that exact, immutable version regardless of which version is current and regardless of a later withdrawal (REQ-REG-070, REQ-REG-025, ADR-REG-003). (3) CON-REG-007's "current version" read is the resolution step of a new Check and otherwise serves non-Check use only; it is not a source of a running Check's configuration. (4) CON-REG-009's return is widened additively with versionNumber, inputName and the document source (documentSourceQueryName, documentTypeColumn, documentPathColumn | documentContentColumn), so it carries everything CON-REG-007 carries; no existing field changes. (5) CON-REG-007 keeps its signature and its DOC caller line for DOC v1; DOC's switch of its fetch-time read to CON-REG-009 with the pinned version is a platform finding (project-registry §10, PF-7, owner DOC, DOC v2).
Consequences: SRS REQ-REG-070, AC-REG-082; contract CON-REG-007 notes and CON-REG-009 widened (additive) with DOC v2 in Called by; backend plan `getServicePackageVersion` returns the widened record; backend TC for a promotion between CHK's resolution and DOC's read. Until DOC v2, the window between CHK's resolution and DOC v1's fetch-time CON-REG-007 call stays open in production only when a load run (a restart) happens during a running Check; it is recorded, not hidden (PF-7).
traces      : REQ-REG-024, REQ-REG-025, REQ-REG-070, ENT-REG-002, US-REG-004
