# ADR-REG-019 — The platform-wide Check limits are named: aias.check.timeout = PT2M, aias.check.max-rows = 100, aias.check.max-file-size = 10MB
Status      : ACCEPTED
Stage       : P1        Module: REG        Version: v1
Context     : AIAS-7 requires every Check to declare its timeout, maximum rows and maximum file size. ADR-REG-006 (confirmed by ADR-REG-013) makes them platform configuration, never service-definition data (RULE-REG-012), but no REG artifact named the property names or defaults, and the hand-off was untracked (gate-analysis finding G7). CHK's and DOC's backend plans (CORE) already declare the group `aias.check.timeout` (Duration), `aias.check.max-rows` (int), `aias.check.max-file-size` (DataSize); DOC's test plan uses a 10 MB maximum file size and a 100-row boundary.
Decision    : The platform-wide Check limits are the environment properties `aias.check.timeout` (Duration, default PT2M), `aias.check.max-rows` (int, default 100) and `aias.check.max-file-size` (DataSize, default 10MB). They apply to every Check of every service, are owned by the CORE phase of the modules that run Checks (CHK for timeout and rows, DOC for file size and rows on document fetch), and are never read from a service definition (REG RULE-REG-012 rejects `timeout`, `max_rows`, `max_file_size`). REG reads none of them. The hand-off is recorded as a platform finding for CHK's and DOC's own gates to confirm (the project-registry's platform-findings section is maintained by the orchestrator, not by REG).
Consequences: REG SRS A2 out-of-scope bullet, business-policies AUTO row and backend plan CORE cite this ADR and the names; no REG schema or API change.
