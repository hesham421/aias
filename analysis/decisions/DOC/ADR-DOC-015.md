# ADR-DOC-015 — DOC records every ended Check and refuses a handover for it; a late upload left by a race is swept at the next end of any Check
Status      : ACCEPTED
Stage       : P1        Module: DOC        Version: v1
Context     : ADR-DOC-008 deletes a Check's Uploaded Documents once, on the Check Engine's end-of-Check notice (CON-DOC-005), and therefore plans no retention purge. Nothing stated what happens when INT hands over an upload (CON-DOC-003) for a Check whose end DOC has already been told — a late or retried call racing the Check's own end. Such an Uploaded Document would have no second deletion trigger and would persist indefinitely, against POL-DOC-015 ("discard them when their Check ends") and raw-idea §12 guardrail 9. DOC is tier 1: it cannot read CHK's or RPT's Check state (that would be a dependency cycle), so it can only rely on what it has itself been told. (Analysis-gate finding G2.)
Decision    : (a) Ordering rule: once the end of a Check has been reported to DOC, no upload is accepted for that Check. The callers uphold it — INT hands over an upload only while its Check is awaiting documents, and CHK sends the end-of-Check notice only after the Check stops accepting documents (recorded as a platform finding for CHK and INT). (b) Safety net in DOC: on the end-of-Check notice, DOC records the Check's identifier as an Ended Check (ENT-DOC-002, PRIVATE, one row per ended Check, holding only the Check identifier as a value and the time; repeating the notice keeps one row — REQ-DOC-060), and rejects every later handover for that Check with the RULE-DOC-009 message (REQ-DOC-061). (c) Race window: a handover that passed the check just before the notice committed can still commit after the delete; every end-of-Check notice therefore also deletes every Uploaded Document whose Check is recorded as an Ended Check (REQ-DOC-062), so such a row lives at most until the next end of any Check.
Alternatives rejected: a time-based retention purge of Uploaded Documents — reintroduces the retention logic ADR-DOC-008 removed and keeps orphaned files for a whole retention window; asking CHK or RPT whether the Check is still open — a tier-1 module reading a higher tier creates a dependency cycle; only a caller guarantee with no DOC check — an orphan would be undetectable if the guarantee were ever broken.
Consequences: P2 adds one small table for ENT-DOC-002 with a unique Check identifier; it holds no request data, so it is kept (one number per ended Check) and needs no purge in this version. CON-DOC-003 gains the rejection "Check already ended" and CON-DOC-005 records the Check and sweeps. P3.1 adds the in-process code `DOC-409-CHECK-ENDED`. Amends the consequence "P2 needs no retention purge" of ADR-DOC-008 only by the sweep of (c); ADR-DOC-008 stays in force.
